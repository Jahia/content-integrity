| 4.0.0   | 8.1.5.0                | <a name="latest"></a><a name="v4-0-0"></a><ul><li>Jahia 8.1.5.0 or later is now required</li><li>Build: the administration screen is built with Yarn 4, pinned by the `packageManager` field of `package.json` and run through corepack, instead of Yarn 1. The Maven build installs it with the `install-node-and-corepack` goal of `frontend-maven-plugin` 1.15.4. To build or run the tests outside of Maven, run `corepack enable` once, then `yarn install`</li><li>UI<ul><li>Rewrote the administration screen in React with the Jahia Moonstone design system. It is now a native administration route instead of an iframe</li><li>The scan tab and the results tab are replaced by a single page: the results of the stored scans are displayed, below the scan which runs if any, and a scan is configured in a dialog opened from the page header</li><li>The scan which runs is displayed with its start date and its logs, pushed by a GraphQL subscription, and its results are displayed when it is over. Each stored scan tells its status, finished, interrupted or failed, and keeps its log</li><li>The configuration dialog of a check validates the integer values and only saves the changed ones</li><li>Results: choose the displayed columns from a dropdown, the path, the workspace, the check name, the error type and the message by default, and display the full value of a truncated cell in its tooltip</li><li>Results: the filters are always displayed, and by default only the errors which make the XML import fail are displayed</li><li>Results: the Refresh button clears the results, without reloading the page: the list of the scans is read again, and no results are displayed until a scan is chosen</li><li>Results: <strong>Delete</strong>, next to the reports, deletes the results of the selected scan, with their CSV and XLSX reports, after a confirmation. It requires the new permission `adminContentIntegrityDelete`, granted to the role `server-administrator` only, and is offered by the GraphQL field `deleteScanResults`</li><li>Results: <strong>Delete all</strong>, in the menu after the title of the results, deletes the results of all the scans except the ones of a running scan, after a confirmation. It requires `adminContentIntegrityDelete` as well, and is offered by the GraphQL field `deleteAllScanResults`</li><li>Results: the page opens, and reopens once reloaded, without any results selected, as after <strong>Refresh</strong>, and displays the same message and <strong>New scan</strong> button whether no scan is stored or none is selected</li><li>Results: <strong>Fix all</strong> runs, after a confirmation, the fix of every error matching the filters. The errors whose check provides no fix, and the ones fixed with a typed value, are skipped. The errors not fixed are tagged in their row</li><li>Results: the errors are displayed as a tree, sorted by workspace then by path: a node with several errors has a row, which can be collapsed, above the rows of its errors, which repeat the columns of the node, such as its path and its workspace, and the only error of a node is displayed in a single row</li><li>Results: a click on a row displays the errors of its node in a side panel, whatever the filters, each with its fix and the fields of its values. The errors fixed with values are linked when the node has several of them: a node is saved only once all its mandatory properties are set, so their values are saved at once, with a single Fix button. <strong>Fix all</strong>, at the bottom of the panel, fixes the errors of the node which can be fixed. The outcome of a fix stays displayed in the last column of the row</li><li>Results: every fix, from **Fix all** or from the panel of a node, and the deletion of the results of all the scans, are run only once confirmed, after the box "Be careful, data are going to be altered in this environment" is ticked, unticked each time the confirmation opens</li><li>Results: the panel of a node describes, above the Fix button of each error, what its fix changes, for example the deletion of a node</li><li>Results: the panel tells when the node of an error has been removed since the scan, for example by the fix of another error, instead of flagging the error without fix. GraphQL: added the field `nodeExists` to the errors</li><li>Results: after <strong>Fix all</strong>, near the results or at the bottom of the panel of a node, a dialog tells how many errors are fixed, how many are skipped and why (already fixed, no fix, fixed with a typed value, virtual node, node removed since the scan), and how many are not fixed and why: the message of the failure, or else what the fix does</li><li>Results: a filter on the fix status, to display the errors fixed, the ones skipped, on which no fix has run, or the ones not fixed, whose fix has run without fixing them. The three statuses are always offered, with their number of errors. The failure of a fix is stored with the results, as their fixed status, and the row of the error tells it once the page is reloaded</li><li>The page fills the screen, with the margins of the administration: the results card reaches the bottom of the screen, with the pagination at its bottom</li><li>The icons of the screen are displayed in a single size</li><li>Added French labels</li><li>Removed the legacy jQuery screen, its JSP views and the `contentIntegrity.ui` configuration</li></ul></li><li>The command `jcr:integrity-fix` is now available, without the `modules.contentIntegrity.devMode` system property</li><li>Checks<ul><li>`AceSanityCheck`: the ACE related errors can be fixed with the `jcr:integrity-fix` command: deletion of the ACE without principal or without ACE type, deletion of the external ACE without valid source ACE or with an invalid ACE type, removal of the invalid values of `j:sourceAce`, recreation of the missing external ACE</li><li>Removed the hidden Groovy scripts dedicated to the cleanup of the ACE, replaced by the fixes of `AceSanityCheck`</li><li>The results of the scans are stored in the JCR, under `/sites/systemsite/files/content-integrity-reports`, instead of a cache lost at each restart: one report per scan, written when it starts, with its status (running, finished, interrupted or failed), its log and its errors. The reports older than 30 days are deleted by a background job, configured by `org.jahia.modules.contentintegrity.reports` (`retentionDays`, `cleanupIntervalHours`). The methods `storeErrorsInCache` and `removeErrorsFromCache` of `ContentIntegrityService` are removed</li><li>A fix reports an error already fixed as fixed, as the API declares it: a property or a mixin already removed, for example by the fix of another error or from other results, no longer ends as not fixed. It concerns `UNDECLARED_PROPERTY`, `UNEXPECTED_PROP`, `UNEXPECTED_TYPE`, the undeclared mixins of `UNDECLARED_NODE_TYPE`, `BROKEN_REF` and `NO_LIVE_NODE`. An error whose node does not exist anymore is not fixable</li><li>Only the errors which have a fix are offered one: a check tells which of its errors it fixes with the new method `SupportsIntegrityErrorFix.isFixable(error)`, true by default. Not fixable anymore: `DIFFERENT_PATH`, `DIFFERENT_PATH_POTENTIAL_FP`, `PATH_CONFLICT` and `DIFFERENT_PT` (`PublicationSanityDefaultCheck`), the differences of properties and mixins of `PublicationSanityLiveCheck`, `BROKEN_REF_TO_VN` and `INVALID_BACK_REF`, `FALLBACK_ON_NAME_WRONG_TYPE`, `INVALID_VALUE_TYPE`, `INVALID_MULTI_VALUE_STATUS` and `INVALID_NODE_VALIDATION`, and the ACL errors which need an analysis. The method `isFixWithValues` of `SupportsIntegrityErrorFixWithValues` is removed: an error is fixed with values when `getFixValuesDefinition` returns their description</li><li>The missing `j:roles` of an access control entry, reported by `PropertyDefinitionsSanityCheck` and by `NO_ROLES_PROP` of `AceSanityCheck`, is filled with roles chosen among the roles which can be given at its place, and the details tell to whom they are granted. Without a value, the right roles can't be guessed and the entry is not fixed</li><li>An access control entry without `j:principal`, reported by `PropertyDefinitionsSanityCheck` and by `NO_PRINCIPAL` of `AceSanityCheck`, is fixed with a user or a group chosen among the ones it can name, in a dropdown grouping the users and the groups, the one its name tells being suggested. From the administration screen, the entry is no longer deleted: the deletion remains the fix without value, as from `jcr:integrity-fix`</li><li>`PropertyDefinitionsSanityCheck`: `INVALID_VALUE_CONSTRAINT` is fixed in the administration screen with a value chosen among the values accepted by the definition, or typed when its constraints are not a list. On a multiple property, the other values are kept. Fix all skips it</li><li>`PagesSanityCheck`: `MISSING_TEMPLATE` is fixed in the administration screen with a template chosen in a dropdown, which lists the templates available to the page, as in the template selector of the editors</li><li>A check which fixes errors with values can fix several errors of a node together, with the new method `SupportsIntegrityErrorFixWithValues.fixErrors(node, errors, values)`, which fixes them one by one by default. `PropertyDefinitionsSanityCheck` and `AceSanityCheck` write all the values, then save the node once</li><li>New fixes<ul><li>`SiteLevelSystemGroupsCheck`: `GROUP_DOES_NOT_EXIST` creates the missing group again, as Jahia creates it with a site: the group `site-privileged` is a member of `privileged`, is granted the role `privileged` on the site and on its folders `users` and `groups`, and its members are the principals granted a role with a privileged access in the site. The server group `privileged` is created again with the groups `site-privileged` of the sites. `MISSING_MEMBERSHIP` adds the group `site-privileged` to `privileged`</li><li>`UserAccountSanityCheck`: `NOT_OWNER` grants the role `owner` to the user on its account node</li><li>`AceSanityCheck`: `INVALID_NODENAME` renames the ACE after its type and its principal, unless an ACE already has this name, or the external ACE has an invalid role or external permissions. `ROLE_DOESNT_EXIST` removes the roles which don't exist, and deletes the ACE left without role, or the external ACE. `INVALID_ROLES_PROP` deletes the external ACE, then the ACL listener creates the right ones from its source ACE.</li></ul></li><li>`LockSanityCheck` runs in the `live` workspace as well, and detects two new errors, both fixed by the check. `LOCK_OF_UNKNOWN_PROCESS`: a node locked by a workflow whose process does not exist anymore, for example removed without ending, which leaves the node locked; the fix releases the lock of the process. `LOCK_PROPERTIES_IN_LIVE`: the lock properties `j:lockTypes` and `j:locktoken` of a node of the `live` workspace which is not locked, copied by the first publication of a node that a workflow locks; the fix removes them</li><li>`ReferencesSanityCheck`: detects `BROKEN_REF_IN_FIELD`, a link of a text whose `##ref:linkN##` placeholder has no referenced node, as left by the deletion of the linked node. Such a link is rendered as `#`. The fix removes the link from the text, keeping its text, as when it is removed in CKEditor, and deletes its `jnt:referenceInField` node</li><li>[bugfix] `ReferencesSanityCheck`, `StaticInternalLinksCheck`: the values are read without the interceptors, which logged a warning `Cannot find referenced item` for each link of a text without a referenced node</li><li>[bugfix] `jcr:integrity-check`: the checks prefixed with `:` in `-c` are skipped, they were run anyway</li><li>[bugfix] `jcr:integrity-printError` and `jcr:integrity-printTestResults`: the descriptions of their arguments, an error to print and the ID of a scan, were wrong. The commands which load the results of a scan print the same message when they can't be found, and the completion of an option value no longer fails when the option is the last typed word</li><li>[bugfix] `PagesSanityCheck`: the default template of a site, `j:defaultTemplateName`, is checked against the page templates available to the site; it was never checked</li><li>[bugfix] `UndeployedModulesReferencesCheck`: the fix of a module installed but not started reports the error as not fixed, and tells to start the module; it reported it as fixed without any change</li><li>[bugfix] `PublicationSanityDefaultCheck`: the fix of `NO_LIVE_NODE` on the content of a module publishes it; it reported it as fixed without any change</li><li>[bugfix] UI: on Jahia 8.1.5, a dropdown of the values of a fix which groups its choices, such as the principal of an ACE, displays the chosen or suggested value</li><li>[bugfix] `NodeNameInfoSanityCheck`: `j:nodename` is no longer checked under `/modules`, where the files of the modules are exposed in development mode by an external provider which does not store it</li><li>[bugfix] `AceSanityCheck`: an ACE without principal or without type was reported as a framework error instead of `NO_PRINCIPAL` or `NO_ACE_TYPE_PROP`</li><li>[bugfix] `AceSanityCheck`: the message of `NO_ROLES_PROP` read "ACEExternal ACE without property j:roles"</li><li>[bugfix] `HomePageDeclarationCheck`: the fix of `MULTIPLE_HOMES` in the default workspace was not saved, and it also removed the flag of the page kept as home, which left the site without home page</li><li>[bugfix] `VersionHistoryCheck`: the fix of `TOO_MANY_VERSIONS` was reported as successful when the purge kept more versions than the threshold, since the versions used by the default and the live nodes can't be purged. It is now reported as not fixed</li><li>[bugfix] `AceSanityCheck`: the fix of `MISSING_EXTERNAL_ACE` was reported as successful when the ACL listener could not create the external ACE, for example because an external ACE for other permissions takes its place. It is now reported as not fixed, and the ACL is no longer published</li><li>[bugfix] `UndeclaredNodeTypesCheck`: the fix of an undeclared mixin failed, since Jackrabbit refuses to remove a mixin whose type is not registered</li></ul></li><li>[bugfix] GraphQL: the results of an unknown scan returned an error instead of null</li><li>[bugfix] GraphQL: `possibleValues` returned an internal error when `withErrorsOnly` was omitted, now false by default, or when `names` was omitted or repeated a column. The arguments `offset` and `pageSize` of `errors` are now required, so a missing one is reported by name instead of an internal error</li><li>GraphQL: removed the argument `uploadResults` of the field `scan`: the CSV and XLSX reports of every scan are written in the JCR, next to its results</li><li>GraphQL: added the fields `choiceLabels`, `choiceGroups` and `description` to `fixValues`, the description of the values which fix an error</li><li>GraphQL: the errors of the scan results are sorted by workspace then by path. Added the fields `nodeErrors`, the errors of a node whatever the filters, and `fixErrors`, which fixes errors together with their values, the filter `fixStatus`, whose values are `fixed`, `skipped` and `notFixed`, and the field `fixFailed` of an error, true when its fix has run without fixing it</li><li>GraphQL: added the field `fixAllErrors` to the scan results, which fixes all the errors matching the filters and returns the number of errors fixed, not fixed, skipped and already fixed, the identifiers of the errors not fixed, the errors skipped counted by reason (`skippedReasons`), and the errors not fixed grouped by check, error type and message (`failures`). The field `fixFailureMessage` of an error tells why its last fix has failed, when it raised an exception</li><li>[breaking] The module exports the package `org.jahia.modules.contentintegrity.api` only: `AbstractContentIntegrityCheck`, `JCRUtils` and `Constants` move to it from `org.jahia.modules.contentintegrity.services.impl`, which is removed, so a custom check must update its imports. The unused methods `setConditions()`, `setDescription()` and `getDescription()` of `AbstractContentIntegrityCheck` are removed, as well as the deprecated API of the errors without error type: the methods `createError()` which take a message instead of a `ContentIntegrityErrorType`, and `ContentIntegrityError.setErrorType()`. Declare the error types with `createErrorType()`. See [How to extend](how-to-extend.md#how-to-extend)</li><li>Documentation: the screenshots of the administration screen in the README are taken by `tests/demo/screenshots.sh`, from the demo, with the ones of the checks, and `yarn docs:pdf` builds `README.pdf` as well as `docs/embedded-tests.pdf`</li><li>Documentation: the checks which rely on the search index or on the modules started on the server, local to each server of a cluster, are listed in the FAQ of the README, and their documentation tells to run them on every server, and not to fix an error reported on some servers only: `TemplatesIndexationCheck`, `PagesSanityCheck`, `AceSanityCheck`, `ReferencesSanityCheck`, `UndeclaredNodeTypesCheck` and `UndeployedModulesReferencesCheck`. Results: the panel of a node tells it as well, under **In a cluster**, for each error of these types, and for `GROUP_DOES_NOT_EXIST`, whose fix finds the members of the group with the search index</li><li>Added Cypress tests covering every error type of every check, its fix, the GraphQL API, the Karaf shell commands with all their options and the administration screen</li><li>Security<ul><li>Pass the name and value of a check configuration as GraphQL variables instead of concatenating them into the query</li><li>New permission `adminContentIntegrityFix`, required to fix the errors from the administration screen or with the GraphQL fields `fixError`, `fixErrors` and `fixAllErrors`. It is added to the role `server-administrator`, and is not granted by `adminContentIntegrity`, so a user who may run the scans and read their results may not fix the errors. The GraphQL field `canFixErrors` tells if the current user may fix the errors</li><li>The scan reports, uploaded under `/sites/systemsite/files/content-integrity-reports`, are readable by the server administrators only. The role `privileged`, which every editor of every site holds on the system site, is denied on the reports folder, when a report is written and when the module starts, so the reports of the previous versions are protected as well</li></ul></li></ul>                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
